---
title: "Notification"
description: "Notifications for the user behind your API key."
---

Notifications addressed to the user your API key authenticates as, plus the two
calls that mark them read.

Each row is one recipient's copy. The shared event lives in the nested
`notification` object, so `viewedAt` and `isArchived` are per recipient while
`notification.title` is not.

## Fields

Every property the API returns for a notification.

| Field | Type | Notes |
| ----- | ---- | ----- |
| `id` | UUID | Unique id of this user's copy of the notification. Read-only. |
| `organizationId` | UUID | Your organization. Taken from the API key. Read-only. |
| `appUserId` | UUID | User the notification was delivered to. Read-only. |
| `notificationId` | UUID | The underlying notification, shared across recipients. Read-only. |
| `viewedAt` | date-time \| null | When this user read it. `null` means unread. Read-only. |
| `isArchived` | boolean | `true` when this user has archived it. Defaults to `false`. Read-only. |
| `notification` | object | The shared notification this copy points at. Read-only. |
| `createdAt` | date-time | When the copy was created. Read-only. |
| `updatedAt` | date-time | When the copy last changed. Read-only. |

<Info>
  Write endpoints exist on this resource but are not supported through the API.
  BuildingSwell produces notifications in response to events. Use the two
  read-state calls below.
</Info>

## Mark channel comments as read

```http
POST /notification/read-channel-comments

{ "channelId": "<uuid>" }
```

## Mark deliverable documents as read

```http
POST /notification/read-deliverable-documents

{ "deliverableId": "<uuid>" }
```

## Find what is unread

`viewedAt` is `null` until the user reads the notification:

```http
GET /notification?viewedAt:isn=true&isArchived=false
```
