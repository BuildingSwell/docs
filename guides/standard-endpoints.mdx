Learn these once and every resource follows the same rules. The examples use
`/project`, and the same paths exist for `/deliverable`, `/stage`, `/comment`, and
the rest.

| Method | Path | What it does |
| ------ | ---- | ------------ |
| `GET` | `/project` | List and filter records |
| `GET` | `/project/{id}` | Get one record |
| `POST` | `/project` | Create one record, or many |
| `PATCH` | `/project/{id}` | Change some fields on a record |
| `PUT` | `/project/{id}?update=<columns>` | Insert or update a record |
| `DELETE` | `/project/{id}` | Permanently remove a record |
| `GET` | `/project/count` | Count matching records |
| `POST` | `/project/count` | Count, with the filter in the body |
| `POST` | `/project/query` | List, with the query in the body |
| `POST` | `/project/group-and-count` | Group by a field and count |
| `PATCH` | `/project/bulk?<filter>` | Change many records at once |
| `PUT` | `/project/bulk?update=<columns>` | Insert or update many records |

Not every resource offers all of them. `timesheet` is read-only, `worker` refuses
hard deletes, and `qc-template` is read and delete only. Each
[resource page](/resources/project) says what it supports, and the
[API reference](/api-reference/overview) lists the concrete paths.

## Four things that trip people up

### `PUT` needs `?update=`

Both `PUT /{id}` and `PUT /bulk` require an `update` query parameter naming which
columns to overwrite when a row with a conflicting unique key already exists.
Without it the request is rejected with `400`.

Pass it as a repeated parameter. A single comma-separated value is not accepted:

```http
PUT /project/<id>?update=name&update=costCode
Content-Type: application/json

{ "name": "Warehouse A", "costCode": "WH-A" }
```

```http
PUT /project/bulk?update=identifier&update=name
Content-Type: application/json

[{ "identifier": "PRJ-1", "name": "Warehouse A" }]
```

### `PATCH /bulk` needs its filter in the query string

A filter in the request body is ignored. Without a filter in the query string the
request fails with `400` and `"No filter provided for updateMany"`, which is
deliberate: it stops you updating an entire table by accident.

```http
PATCH /project/bulk?isArchived=false
Content-Type: application/json

{ "costCode": "WH-A" }
```

### Bulk delete does not exist

`DELETE /{resource}/bulk` returns `403` on every resource. To remove many records,
archive them with `PATCH /bulk`. See
[archiving and deleting](/guides/archiving-and-deleting).

### Archived records are hidden by default

List and count endpoints filter to `isArchived eq false` unless you say otherwise:

```http
GET /project?isArchived=true
```

## Creating one record or many

`POST` takes either an object or an array. An object comes back as `value`, an
array as `values`:

```bash
# One
curl -X POST "https://app.buildingswell.com/api/v2/project" \
  -H "X-API-Key: <key>" -H "Content-Type: application/json" \
  -d '{ "name": "Warehouse A" }'

# Many
curl -X POST "https://app.buildingswell.com/api/v2/project" \
  -H "X-API-Key: <key>" -H "Content-Type: application/json" \
  -d '[{ "name": "Warehouse A" }, { "name": "Warehouse B" }]'
```

## When your filter is too long for a URL

Long filters, big id lists, and wide `select` lists hit URL length limits at the
load balancer before they reach us. Every resource has `POST` twins that take the
same options in the body:

| Instead of | Use |
| ---------- | --- |
| `GET /project` | `POST /project/query` |
| `GET /project/count` | `POST /project/count` |

```bash
curl -X POST "https://app.buildingswell.com/api/v2/project/query" \
  -H "X-API-Key: <key>" -H "Content-Type: application/json" \
  -d '{ "id": ["<uuid>", "<uuid>"], "select": ["id", "name"], "pageSize": 200 }'
```

See [querying](/guides/querying) for the filter, sort, and join syntax these share.
